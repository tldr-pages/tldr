# מדריך סגנון

עמוד זה מפרט את הכללים הייחודיים לעמודי `tldr` בעברית.
לכללים כלליים, יש לעיין ב[מדריך הסגנון הראשי](style-guide.md).

## מבנה כללי

הפורמט הבסיסי של כל עמוד צריך להתאים לתבנית הבאה ולכלול עד 8 דוגמאות:

```md
# command name

> תיאור קצר וממצה של הפקודה.
> רצוי בשורה אחת; שתיים מקובלות במידת הצורך.
> למידע נוסף: <https://example.com/command_name/help/page>.

- תיאור הפעולה:

`command_name options`

- תיאור הפעולה:

`command_name options`

...
```

דוגמה:

```md
# krita

> תוכנת ציור ושרטוט המיועדת לאמנים דיגיטליים.
> ראו גם: `gimp`.
> למידע נוסף: <https://docs.krita.org/en/reference_manual/linux_command_line.html>.

- הפעלת Krita:

`krita`

- פתיחת קבצים מסוימים:

`krita {{path/to/image1 path/to/image2 ...}}`

- הפעלה ללא מסך פתיחה:

`krita --nosplash`

- הפעלה עם סביבת עבודה מסוימת:

`krita --workspace {{Animation}}`

- הפעלה במסך מלא:

`krita --fullscreen`
```

יש לסדר את שורות הפתיח, כולל הערות, פקודות משנה, `ראו גם` ו-`למידע נוסף`, לפי [הסדר המוגדר במדריך הראשי](style-guide.md#heading-order).

> [!NOTE]
> שם הקובץ והכותרת חייבים להתאים לשם הפקודה בדיוק. בכותרת אפשר להשתמש באותיות רישיות או קטנות, אך שמות קובצי Markdown חייבים להיכתב באותיות קטנות.

קיים linter שאוכף פורמט זה.
הוא רץ אוטומטית על כל Pull Request, אך ניתן להתקין אותו לבדיקה מקומית:

```sh
npm install --global tldr-lint
tldr-lint path/to/tldr_page.md
```

לשימושים נוספים ב-`tldr-lint`, כמו בדיקת תיקייה שלמה, אפשר לעיין
[בעמוד `tldr-lint`](https://github.com/tldr-pages/tldr/blob/main/pages/common/tldr-lint.md). לחלופין, ניתן להשתמש בקיצור `tldrl`.

## ניסוח תיאורים

- תיאור הפקודה יהיה קצר ולא יפנה לקורא.
- תיאורי הדוגמאות ייכתבו בשם פעולה.

| אנגלית | יש להשתמש | אין להשתמש |
| --- | --- | --- |
| Show the files | הצגת הקבצים | הצג / הציגו את הקבצים |
| Delete a file | מחיקת קובץ | מחק / מחקו קובץ |
| Copy a file | העתקת קובץ | העתק / העתיקו קובץ |
| List all packages | הצגת כל החבילות | הצג / הציגו את כל החבילות |

הנוסח הקבוע `ראו גם` אינו תיאור של פקודה או דוגמה.

דוגמה:

```md
- הצגת כל הקבצים:

`ls`
```

ולא:

- `הצג את כל הקבצים` (ציווי יחיד זכר)
- `הציגו את כל הקבצים` (ציווי רבים)
- `הקבצים יוצגו` (סביל)
- `תציג את כל הקבצים` (גוף שני עתיד)

## מונחים טכניים

### כללי

- מונחים טכניים שאין להם תרגום מקובל ונפוץ בעברית יישארו באנגלית.
- שמות של פקודות, פקודות משנה, אפשרויות ומזהים יישארו כפי שהם וייכתבו בתוך גרשיים הפוכים (backticks).
  לדוגמה: `git commit`, `--verbose` ו-`HEAD`.
- מונחים שיש להם תרגום מקובל יתורגמו:

| אנגלית | עברית |
| --- | --- |
| file | קובץ |
| directory / folder | תיקייה |
| path | נתיב |
| output | פלט |
| input | קלט |
| version | גרסה |
| help | עזרה |
| option / flag | אפשרות / דגל |
| command | פקודה |
| pattern | תבנית |
| permission | הרשאה |
| process | תהליך |
| variable | משתנה |
| string | מחרוזת |
| symbolic link | קישור סמלי |

### שמות תוכנות ופרויקטים

שמות תוכנות ופרויקטים נכתבים בכתיב המקורי ובאותיות רישיות לפי הצורך.
בתיאורים יש לכתוב Git ו-Docker, ואילו שמות הפקודות נכתבים כפי שמפעילים אותן ובתוך backticks, למשל `git` ו-`docker`.

## מצייני מיקום (Placeholders)

- אין לתרגם מצייני מיקום. לפי [הכלל לשפות הנכתבות מימין לשמאל](translation-templates/common-arguments.md), יש לשמור אותם באנגלית כדי שסדר התווים לא ישתבש.
- יש להשתמש ב-`{{path/to/file}}`, ולא ב-`{{נתיב/אל/קובץ}}`.

כללים נוספים למצייני מיקום מפורטים ב[מדריך הסגנון הראשי](style-guide.md#placeholder-syntax).

## קישור "למידע נוסף"

- יש להשתמש בתבנית הבאה:

```md
> למידע נוסף: <https://example.com>.
```

- ככלל, יש לשמור את הקישור מהעמוד באנגלית, כל עוד הוא תקין ועדכני.

## ראו גם

- לתרגום "See also:" יש להשתמש בתבנית הבאה:

```md
> ראו גם: `example`.
```

## הערות

- הערה תתחיל בנוסח `הערה:`. לדוגמה:

```md
> הערה: השימוש בפקודה זו אינו מומלץ עוד; יש להשתמש בפקודה `example` במקומה.
```

## פקודות משנה

- לאזכור עמודי תיעוד של פקודות משנה יש להשתמש בתבנית הבאה:

```md
> לחלק מפקודות המשנה, כגון `example`, יש תיעוד שימוש נפרד.
```

## שמות חלופיים (Aliases)

עמודי שמות חלופיים צריכים להיראות כך:

```md
# command_name

> פקודה זו היא שם חלופי לפקודה `original-command-name`.

- הצגת התיעוד של הפקודה המקורית:

`tldr original-command-name`
```

- תבניות מתורגמות מראש לעמודי שמות חלופיים זמינות ב[קובץ התבניות](https://github.com/tldr-pages/tldr/blob/main/contributing-guides/translation-templates/alias-pages.md).

## הדגשה

אין להשתמש בהטיה, בהדגשה או בעיצוב טקסט אחר בעמודים. אלה שמורים להדגשת מצייני מיקום על ידי הלקוח.

## פסיק סידורי

בעברית, כללי הפסיק הסידורי (Oxford comma) של האנגלית אינם רלוונטיים. יש להשתמש בפיסוק עברי תקני.

## מצב אינטראקטיבי

- תיאור של פקודה במצב אינטראקטיבי יתחיל בסימון `[אינטראקטיבי]`. לדוגמה:

```md
- [אינטראקטיבי] הצגת המצב הנוכחי:

`status`
```

## עזרה וגרסה

- בדרך כלל, פקודות עזרה וגרסה מופיעות, בסדר הזה, כשתי הדוגמאות האחרונות בעמוד, כדי להציג תחילה דוגמאות שימושיות יותר. אפשר להחליף אותן בדוגמאות שימושיות אחרות במידת הצורך.
- לשמירה על עקביות, יש להשתמש בנוסחים `הצגת עזרה` ו-`הצגת גרסה`.
- מומלץ לתעד את דוגמאות העזרה והגרסה כאשר הפקודה משתמשת באפשרויות לא שגרתיות, למשל ב-Windows.
